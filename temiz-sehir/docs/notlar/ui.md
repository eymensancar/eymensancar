# ui.js — notes (owner: ui)

File: `www/js/ui.js`. Contract: MIMARI §4.7, §4.9 (UI side), §6. Tests: `test/ui/run.mjs` (fakes in `test/ui/fakes/`), screenshots in `test/ui/shots/{land,land2,port}/`.

## What is implemented
- **Exports:** `init, update, resize, save, load, toast, openPanel, closePanel` (nothing else).
- **HUD** (DOM over the canvas, chunky rounded casual style, system rounded font stack, one inline-SVG icon set drawn in the file, no emoji):
  - money chip with count-up (`feedback.coinCounterRollS`, ease-out, delayed while flying coins are in the air, bump on landing; text written only when the integer changes, tabular numbers so the width does not jitter);
  - **next-goal chip always visible**: icon, name, price, progress bar; endowed progress (first goal starts 1/3 filled), glow at ≥ 80 %, green "Alabilirsin!" pulse when affordable, "Hepsi alındı" at the end;
  - bag/tank meter (container switches to the tank while mounted), green → amber at 70 %, **full state**: red pulsing chip "Çanta dolu / Depo dolu" + shop icon, plus an **on-screen indicator** to the nearest active sell point (pin above the target when it is on screen, clamped to the screen edge with a rotating arrow when it is off screen or behind; distance in metres; kept above the thumb zone);
  - district % ring (SVG stroke-dashoffset), one decimal below 10 % so early progress moves, 25/50/75 milestone dots;
  - compass strip: shop, drop-off (when active), robots (their colours), and from `completion.stragglerHintAt` the 3 nearest dirty 6 m blocks from `trash.blockSums()` (2 Hz) plus a one-time toast;
  - robot chips (colour, LED amber when full/going to sell, blinking when unloading);
  - boost timer chip ("2 kat: 87 sn") only while the boost is active;
  - **context button** (right thumb): top offer's icon + label, colour per kind (yellow tool, green shop, pink cart), press → `input:button {down:true}` + `ui:offer {id, owner}`, release → `{down:false}`; E/Space do the same; `shop` opens the shop panel. Idle (no offer) shows the current tool dimmed;
  - **secondary context button** (smaller, blue) for a second offer with priority ≥ 50 (see contract issue 1);
  - tool buttons (hands/broom) next to the context button when more than one is owned and not mounted → `ui:tool`;
  - stick visuals from `player.input().stick` (+ faint ghost stick at the resting place on touch devices);
  - toasts (max 3, deduplicated), "+N" coins-to-be batched every `feedback.coinPopupBatchS` near the bag, robot "+coins" projected from the unload position, valuable "+50" gold popup, sale coin shower to the counter (3–14 coins by amount), confetti (DOM pool, 56 / 110 pieces, transform/opacity only);
  - milestone banner 25/50/75 (title, bonus, ring pulse, confetti); the 50 % one carries the one-time boost offer (`boost.offerOnMilestone`) with "Hayır, teşekkürler";
  - **100 %**: after `completeDelayS` (camera lift) the "Mahalle tertemiz!" card: 100 % ring, time / items / coins (`economy.stats()`), "Sıradaki mahalle: yakında", promo cards, big confetti;
  - first-60-seconds hints from `CONFIG.hints` (show triggers: time, bagFull, canAffordFirst, buy:<id>, enterCart; done on pickup, sale, purchase, move, sweep, enterCart, nozzleToggle; one at a time, queued, each once, saved, max 4 before the broom): one-word bubble anchored to the button / stick / sell-point indicator, a tapping-hand icon for "Topla", a ghost thumb for "Yürü"; hidden while a panel is open; `nozzle`/`cart` hints are suspended (not marked done) when the player gets out;
  - "while you were away" card: honest numbers, coins already added, "(2 saatlik sınır)" when the absence exceeded the cap;
  - debug overlay with `?debug` (4 Hz): fps, frame/js/render ms, dpr, draw calls, triangles, max changed cells per window, per-module ms.
- **Panels** (`openPanel`): `shop` (cards sorted by price: icon tile, name, effect "before › after" computed from CONFIG, description, price button, affordability bar + "N altın daha", "Sıradaki" ribbon; owned strip; side column with the boost button / active timer / cooldown, robot list with names, colours, state and load, and the **labelled promo slot** "Bizim diğer oyunlarımız" with placeholder art, no links), `pause`/`settings` (sound, city sound, haptics, language TR/EN, look speed 5 steps, cart steering camera/tank, graphics auto/high/battery, reset save with an inline confirm), `ad` (mock ad overlay, labelled "Reklam (deneme)", `boost.mockAdS`, then `ui:adWatched {kind:'boost'}`; returns to the shop if opened from there), `complete`, `away`. `pause`, `settings`, `ad` pause the game (`ctx.setPaused('panel', …)`); shop/complete/away do not (robots keep working while you shop). Every open/close emits `ui:panel`.
- **Haptics**: no owner in the contract; ui owns the setting so it drives them (Capacitor Haptics plugin if present, else `navigator.vibrate` on touch after user activation): light on pickups (≤ 15/s) and button presses, medium on sale and full bag, heavy on purchase and milestones.
- **Layout:** landscape first (844×390, 932×430), portrait reflows by class (`ctx.view.portrait`). Safe areas through `--sat/--sar/--sab/--sal`. All buttons ≥ 44×44 (checked by the test in every shot). Nothing but the context/secondary/tool buttons in the bottom thumb zones; the indicator is clamped above them.
- **Save:** `{ v:1, settings, hintsDone, hb (hints shown before the broom), msBoost, complete }`. Load tolerates missing fields; a `?lang=` URL flag wins over the saved language.

## Contract issues (Sözleşme sorunları)
1. **Offer priorities make the nozzle unreachable with one button.** §4.9 gives `exit` 90 > `nozzle` 80, and only the top offer is on the button, so while driving the button always says "İn". I added a secondary button for a second offer with priority ≥ `U.secondaryMinPriority` (50): while driving it shows the nozzle. Suggest: swap to `nozzle` 90 / `exit` 80 (nozzle on the big button) and bless the secondary button in §4.9.
2. **Strings missing from STR.** ui falls back to its own `FB_STR` table (tr + en) for: `pct, district_clean, settings, ambient, haptics, sensitivity, steer_mode, steer_camera, steer_tank, quality, q_auto, q_high, q_low, language, on, off, reset_confirm, reset_yes, cancel, away_title, away_body, away_coins, away_cap, promo_label, ad_tag, boost_on, robots_title, robots_none, robot_idle, robot_clean, robot_travel, robot_unload, robot_name_1..4, robot_tag, u_items, u_m, u_mps, u_robots, u_points, goal_ready, all_bought, owned_title, dist_m`. Design should move them into `STR` (same keys); ctx.t() wins as soon as STR has a key.
3. **Robot names and colours** are not in CONFIG, so economy's meshes and ui's chips/list could disagree. ui uses `robot.name`/`robot.color` if `economy.robots()` entries carry them, else `UI_DEFAULTS.robotColors` (#ff8a3d, #33b5ff, #a66bff, #36d07a) and names Pırıl, Fırfır, Şimşek, Pamuk. Suggest `CONFIG.robot.colors/names`.
4. **Offline result has no event.** ui diffs coins (`economy.coins()`) and units (`trash.totalUnits()`) between `ui.load` and its `game:ready` handler (economy subscribed earlier, so a synchronous catch-up is included) and the same around `app:pause`/`app:resume`. If economy spreads the catch-up over frames the numbers would be partial. ui also listens to a proposed `economy:offline { units, coins, awayS }` and prefers it. Suggest adding it to §6.
5. **Settings that other modules must read:** `state.settings.sens` (look speed multiplier, player), `steer` ('camera'|'tank', tools' cart; default `CONFIG.cart.controlMode`), `quality` ('auto'|'high'|'low', main's DPR), `haptics`. ui also emits an extra `ui:settings` (payload `ctx.state.settings`) on change. None of them is in §4/§6 yet.
6. **Reset save:** main saves again on `pagehide`, which would undo `ctx.save.clear()` + reload. ui sets `nosave` in `ctx.params` first (main checks `params.has('nosave')`). A `ctx.save.reset()` in main would be cleaner.
7. Promo cards: the brief says promos only in the shop; TASARIM/CONFIG (`promo.onCompleteCards: true`) also put two cards on the completion card. Both are implemented (the completion card is a natural pause); the flag turns the second off.

## Tunables
`UI_DEFAULTS` at the top of ui.js (overridable by a future `CONFIG.ui`): near-goal 0.8, endowed 1/3, toast 2.2 s, milestone card 4.2 s (9 s with the boost offer), completion delay 3.2 s, confetti 56/110, coin fly max 14, away card ≥ 60 s, offline cap wording 7200 s, haptics ≤ 15/s, compass span 200°, slow refresh 10 Hz, debug 4 Hz, robot colours/names, look-speed steps 0.6–1.7, secondary button min priority 50. Timings from `CONFIG.feedback` (coinCounterRollS, coinFlyS, coinPopupBatchS, milestoneConfettiS).

## Verified (how) vs assumed
- **Verified, headless Chromium (SwiftShader) with fakes** (`node test/ui/run.mjs`): 28 states × 3 viewports (844×390 and 932×430 with notch safe areas, 390×844 with top/bottom safe areas) screenshotted and looked at over spike screenshots; three review rounds fixed: button styles lost to a reset rule, a class-name clash that made the context button invisible, NaN indicator when the target is exactly behind, tap-hand covering the label, unreachable nozzle, 50 % card too wide, confetti under panels, ring text overflow, portrait shop grid overflow, portrait boost chip over the compass, hint bubble over the indicator label, nozzle hint clipped at the portrait edge, tool buttons not hiding while driving (four review rounds in total). The script checks every visible button ≥ 44 px, HUD groups not overlapping or off screen, panels inside the viewport, no clipped text, no console errors. The button contract (`input:button` down/up + `ui:offer {id, owner}` via E key) is asserted. Last full run: 0 errors, 0 small targets, 0 overlaps.
- **Per-frame cost:** `ui.update` 0.008–0.016 ms/frame (mean of 2 000 frames, busy state: stick active, indicator visible, compass markers, counter rolling, 3 robots), desktop CPU. Budget 0.6 ms. Hot path writes the DOM only on change (numeric caches before building transform strings); 10 Hz slow tick for bag/ring/goal/robots/tools; layout is read only on resize. Draw calls: 0.
- **Assumed / not verified:** real iPhone rendering (SF Pro Rounded via `ui-rounded` is only on Apple devices; headless used a fallback sans), touch feel, haptics on device, WAAPI/compositor cost on WebKit, the real modules' event timing (tested against fakes that follow §4/§6).

## Known weak points
- The shop shows ~1.5 rows of cards at 390 px height (scrolls); the settings panel scrolls too.
- The 50 % banner covers the compass and bag meter for up to 9 s (it can be dismissed in one tap).
- Edge indicator projects with the camera matrices in `ui.update` (after player wrote the pose; calls `camera.updateMatrixWorld()`).
- Hint "walk" is marked done by any movement before 0:45 (so it never nags a player who already moved).
